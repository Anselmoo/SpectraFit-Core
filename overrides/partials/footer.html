{#- Footer override, at overrides/partials/footer.html — same custom_dir search path overrides/main.html / overrides/home.html / overrides/partials/tabs-item.html already use (see their own header comments). This is Zensical's own bundled partials/footer.html (prev/next page nav + `partials/copyright.html` + `partials/social.html`), with a new `.sf-footer-columns` sitemap block inserted above them. cupertino-council pass, 2026-08-02, round 2. Round 1 added a single flat link row (GitHub / Release Notes / Security / License) — rejected on review: every one of those is already a top-nav tab or the header's repo icon, so it was pure duplication, not new information. Redesigned as a real multi-column footer, Apple-pattern: columns group DEEPER links than the top nav exposes (e.g. "Getting Started" the tab vs. Installation/ Quickstart the actual sub-pages), the way Apple's own footer repeats a top-level category name but fans it out into its real sub-items rather than repeating the exact same link. Tension resolutions (fixed precedence Usability > Reduction > Craft > Hierarchy > Metaphor): 1. Craft wanted the visual richness of Apple's real multi-column mega- footer; Reduction required staying at this project's own scale (6 nav sections, not Apple's hundreds of products). Resolved: Reduction wins on COUNT (4 columns, ~4 links each) but Craft wins on STRUCTURE (real columns with headers, not a flat list) — a compact version of the real pattern, not a shrunken imitation of it. 2. Hierarchy wanted the footer's visual weight to stay below page content; Usability required the links still be legible/scannable at the page's own type scale. Resolved: Usability — footer text sized at 0.75rem (one step up from the 0.7rem copyright line), not smaller. Design identity: a real sitemap, organized by what a reader would actually look for at the bottom of a long page — not a second copy of the header, not a copyright afterthought. -#}
