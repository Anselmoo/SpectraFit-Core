Verified by temporarily setting site_url and rebuilding: the `| url` filter is page-relative-depth-aware (`./images/...` at the site root, `../images/...` one level down), so `config.site_url ~ ('images/social-card.png' | url)` is actively wrong on any non-root page once site_url is set (the `../` walks back out of the site_url's own path prefix, e.g. ".../spectrafit-core/../images/..."). The safe pattern is a plain site-root-relative concat with NO `| url` filter: `(config.site_url or '') ~ 'images/social-card.png'`. Today (site_url unset) this renders the bare relative path `images/social-card.png` (still not spec-perfect, and only correct as-is at the site root today — verified live: a subpage such as site/getting-started/installation/index.html emits the same document-relative `images/social-card.png`, which resolves incorrectly from that depth; least-broken option available while site_url stays unset).
