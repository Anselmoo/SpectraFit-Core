# Graph JSON executed by lmfit

A SpectraFit-Core `FitGraph` serialized to JSON (`FitGraph.model_dump_json()`) is a
complete, language-neutral description of a model: nodes (kernel + parameters with
value, bounds, `vary`, `expr`) and expression edges. This folder holds a second
implementation that executes such a file without SpectraFit-Core: it builds the same
model in [lmfit](https://lmfit.github.io/lmfit-py/) (`Model` / `Parameters` with `expr`
constraints) and fits it there.

| File | What it is |
|---|---|
| `graph_to_lmfit.py` | The translator. Reads a graph JSON file only (imports `json`, `numpy`, `scipy.special`, `lmfit`, `pydantic`; never `spectrafit_core`), writes lmfit source code and executes exactly that source. `python graph_to_lmfit.py GRAPH.json` prints the lmfit code. |
| `fe_l23_constrained.graph.json` | The Fe L2,3 EELS constrained model (Fe2O3, 700 to 735 eV) as a graph JSON file: the components, bounds, default start and four expression edges of the EELS solver cross-check. |
| `fe_l23_lmfit.py` | Fits that one file twice, with SpectraFit-Core and with the lmfit translation, from the same start with the same bounds on the same data, and prints both model definitions side by side. |

The graph's JSON Schema is `python/spectrafit_core/graph.schema.json`, generated by
`scripts/export_graph_schema.py` from `FitGraph.model_json_schema()`;
`tests/unit/spectrafit_core/test_graph_schema_file.py` fails when the file is stale.

```bash
uv run python reproducibility/interop/graph_to_lmfit.py reproducibility/interop/fe_l23_constrained.graph.json
uv run python reproducibility/interop/fe_l23_lmfit.py --out DIR
uv run python scripts/export_graph_schema.py [--check]
```

## Names

A parameter `node.param` becomes the lmfit parameter `node__param` (lmfit `prefix`
`node__`). Node ids and parameter names must be valid lmfit names and the mapping must
be one-to-one; a collision (for example node `a__b` with parameter `c` and node `a` with
parameter `b__c`) raises and names both keys.

## Parameters

| Graph field | lmfit | Note |
|---|---|---|
| `value`, `min`, `max` (`null` = unbounded) | `value`, `min`, `max` | |
| `vary` | `vary` | |
| `expr` (per parameter) | `expr` | translated like an edge expression |
| `scale` | not mapped | a conditioning factor for the SpectraFit-Core solver's working variable; it does not change the model. Recorded in the translation notes when set. |
| `min` / `max` of a tied parameter | `min=-inf`, `max=inf` | SpectraFit-Core evaluates a tied parameter from its expression and does not clip it to its own bounds; lmfit would clip. The bounds are therefore not passed to lmfit and the translation notes say so. |

Graph-level fields: `schema_version` must be `0.1`. A node with `dataset_index` set
(multi-dataset scoping) raises with the node id: an lmfit `Model` has no per-dataset
scope. A parameter the kernel does not have, a kernel parameter missing from the node,
an unknown key anywhere in the file, an edge whose target is already tied (by another
edge or its own `expr`) and an empty graph each raise with the offending name.

## Expression grammar and its lmfit `expr` equivalent

The engine grammar (`crates/spectrafit-graph/src/expr.rs`):

```text
expr    := term (("+" | "-") term)*
term    := factor (("*" | "/") factor)*
factor  := NUMBER | REF | "(" expr ")" | "-" factor
REF     := IDENT "." IDENT
```

| Construct | Engine | lmfit `expr` (asteval) |
|---|---|---|
| number literal (`2`, `0.5`, `1e-3`, `2.5E+4`) | `f64` parse | Python float literal, written with `repr` (a literal that overflows to infinity is written `1e999`, which Python also reads as infinity) |
| reference `node.param` | flat key lookup | `node__param` |
| `a + b`, `a - b`, `a * b`, `a / b` | left-associative, `*` `/` before `+` `-` | the same operators, same precedence and associativity; parentheses written where the tree needs them |
| `( ... )` | grouping | grouping |
| unary `-x` | binds tighter than `*` / `/` | Python unary minus, same binding |

Every construct of the grammar has an lmfit `expr` equivalent; there is no unmappable
construct. The translator parses each expression with its own recursive-descent parser
that follows `expr.rs` token for token and re-emits it from the parse tree, so anything
outside the grammar (a function call such as `exp(g.sigma)`, `**`, `^`, a bare name, a
dangling operator) raises with the edge's target and expression
instead of being passed to asteval. Two behaviours differ at run time and are not
constructs: a division by zero inside an expression is an engine error (the tied value
keeps its previous value) and an asteval error in lmfit; a reference to a parameter the
node does not have fails at fit time in the engine and at translation time here.

## Kernels

**Rule (fixed before the round-trip test was written).** A kernel has an lmfit
counterpart when, on the kernel's documented parameter domain, the SpectraFit-Core
kernel as the engine computes it equals a sum of `lmfit.lineshapes` functions (plus a
constant or polynomial term) under a closed-form map of its parameters. The map is one
Python function per kernel in `graph_to_lmfit.py`. An approximation of the same function,
a piecewise branch selection, a shift or normalisation lmfit has no parameter for, or an
n-D coordinate has no counterpart. A kernel without a counterpart raises with its name and
node id; it is never dropped.

Kernels with an lmfit counterpart (20):

| Kernel | lmfit | Map |
|---|---|---|
| `constant` | `ConstantModel` function | `c` |
| `linear` | `linear` | `slope`, `intercept` |
| `quadratic` | `parabolic(a, b, c)` | `a = A`, `b = -2 A c0`, `c = A c0^2 + offset` (expanded form; loses digits when `x` and `c0` are large and close) |
| `gaussian` | `gaussian` | `amplitude = A sqrt(2 pi) sigma` |
| `lorentzian` | `lorentzian` | `amplitude = A pi sigma` |
| `voigt` | `lorentzian` + `gaussian` | `f A pi sigma` and `(1 - f) A sqrt(2 pi) sigma`, same `sigma` |
| `pseudo_voigt` | `lorentzian` + `gaussian` | as `voigt`, `fraction` clipped to [0, 1] as the engine does |
| `arctan_step` | `step(form="arctan")` | identical |
| `tanh_step` | `step(form="logistic")` | `sigma_lmfit = sigma / 2` |
| `erfc_step` | `step(form="erf")` | `sigma_lmfit = -sigma sqrt(2)` (falling step) |
| `fano` | `breit_wigner` | `sigma_lmfit = 2 gamma` |
| `breit_wigner` | `breit_wigner` | identical |
| `double_exponential` | `exponential` + `exponential` | `decay = 1 / lam` |
| `saturating_exponential` | constant - `exponential` | `amplitude - exponential(amplitude, 1 / rate)` |
| `skewed_gaussian` | `skewed_gaussian` | `amplitude = A sqrt(2 pi) sigma` |
| `exp_gaussian` | `expgaussian` | identical (lmfit uses the direct form, the engine an `erfcx` split; equal where neither overflows) |
| `doniach_sunjic` | `doniach` | `amplitude = A sigma^(1 - gamma)` |
| `pearson7` | `pearson7` | `sigma_lmfit = sigma / sqrt(2^(1/m) - 1)`, `amplitude = A sigma_lmfit Gamma(1/2) Gamma(m - 1/2) / Gamma(m)` (`m > 0`, `m != 1/2`) |
| `moffat` | `moffat` | identical |
| `cauchy_dispersion` | constant + `powerlaw` + `powerlaw` | `a + powerlaw(b, -2) + powerlaw(c, -4)` on the domain `x > 0` |

Kernels without an lmfit counterpart (17):

| Kernel | Reason |
|---|---|
| `gaussian2d`, `gaussian_nd` | n-D coordinates; the translator and `evaluate` are 1-D |
| `true_voigt` | the engine normalises to peak height (divides by `Re w(z0)`, a function of `sigma` and `gamma`); lmfit `voigt` is area-normalised (`amplitude / (sigma sqrt(2 pi))`). Both evaluate the Faddeeva function at full double precision. |
| `log_normal` | lmfit `lognormal` carries a `1/x` normalisation and a log-space centre |
| `split_gaussian`, `split_pearson7` | piecewise branch on `x < center` |
| `students_t` | lmfit `students_t` has no width parameter |
| `asym_ir`, `harmonic_ir`, `tauc`, `kww`, `power_saturation`, `power_law_offset`, `mgh09_rational`, `rational_cubic`, `generalised_logistic`, `exp_over_linear` | no lmfit lineshape of this form |

## Acceptance measures (fixed before implementation)

- **Round trip** (per kernel with a counterpart, and on composite graphs with expression
  edges and per-parameter `expr`): at the same parameters, `max |f_lmfit - f_sfc| <=
  1e-10 * max |f_sfc|` over the test grid, where `f_sfc` is `spectrafit_core.evaluate`
  and `f_lmfit` is the translated model's `eval`. Tied values come from lmfit's `expr`
  evaluation and are checked against a direct evaluation of the graph expression.
- **EELS comparison** (`fe_l23_lmfit.py`): data `DspecTi3wqG.msa` between 700 and 735
  eV; model `fe_l23_constrained.graph.json` (default start, the cross-check's main
  bounds); SpectraFit-Core `fit` with `FitOptions(solver="lm")` and lmfit
  `Model.fit(method="leastsq")`, each with its defaults, as in the cross-check. Both fits
  report RSS, every parameter with its standard error, termination (success, message,
  evaluation counts) and stationarity by the cross-check measure: the Gauss-Newton
  predicted decrease divided by RSS at the endpoint, with the central-difference
  Jacobian over the free parameters (`h = 6.06e-6 max(|theta|, 1e-3)`), parameters at an
  active bound (`1e-4` of the bound range) whose gradient points outward held, stationary
  when `<= 1e-6`. Both endpoints are evaluated with the same model function
  (`spectrafit_core.evaluate` with ties applied), and the lmfit model is checked against
  it at both endpoints to `1e-10` relative.
